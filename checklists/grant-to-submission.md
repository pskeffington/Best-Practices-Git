# Grant-to-Submission Checklist

## 1. Opportunity control

- [ ] Live funding opportunity URL is recorded.
- [ ] Source was re-verified within the configured freshness window.
- [ ] Deadline, time zone, and submission portal are confirmed.
- [ ] Applicant eligibility is confirmed.
- [ ] Required registrations are complete or explicitly gated.
- [ ] Required prime/subaward/partner structure is known.
- [ ] Current sponsor guide and opportunity-specific instructions are saved or linked.
- [ ] Current review criteria and point allocations are captured.

## 2. Sponsor profile

- [ ] Correct sponsor profile is selected.
- [ ] Profile assumptions were checked against the live opportunity.
- [ ] Required sections are present.
- [ ] Page limits and attachment boundaries are confirmed.
- [ ] Sponsor-specific forms handled outside the narrative compiler are identified.

## 3. Evidence and positioning

- [ ] Literature/evidence matrix is current.
- [ ] Important quantitative claims have verified sources.
- [ ] Preliminary-data claims resolve to a project artifact.
- [ ] Competing or related funded work was reviewed where relevant.
- [ ] The proposal states a precise problem and gap.
- [ ] The proposed contribution is differentiated from routine implementation.

## 4. Aims / objectives architecture

- [ ] Overall objective is explicit.
- [ ] Central hypothesis or premise is explicit when appropriate.
- [ ] Each aim/objective is bounded and measurable.
- [ ] Aims are not merely lists of experiments.
- [ ] Aims are not unnecessarily dependent on one another.
- [ ] Each aim maps to evidence, method/work, risk, alternative, deliverable, timeline, and budget.
- [ ] Expected outcomes and overall impact are explicit.

## 5. Significance / need

- [ ] Importance of the problem is supported by evidence.
- [ ] Current state of knowledge/practice is accurate.
- [ ] The key gap is explicit.
- [ ] Consequence of leaving the gap unresolved is clear.
- [ ] Sponsor mission relevance is explicit.
- [ ] Need evidence is not misrepresented as intervention-effectiveness evidence.

## 6. Innovation

- [ ] Current practice/baseline is defined.
- [ ] Proposed difference is specific.
- [ ] Innovation type is clear: conceptual, technical, methodological, implementation, or novel use of existing methods.
- [ ] Innovation claim is not routine software development dressed as novelty.
- [ ] Innovation is connected to expected impact.

## 7. Approach and feasibility

- [ ] Design/activity is clear for each aim.
- [ ] Data/population/source is defined.
- [ ] Endpoints or acceptance criteria are defined.
- [ ] Analysis/evaluation method is defined.
- [ ] Responsible roles are named.
- [ ] Milestones are measurable.
- [ ] Major risks are explicit.
- [ ] Alternative strategies or go/no-go rules exist.
- [ ] Feasibility has evidence.
- [ ] Scope fits period and resources.

## 8. Reviewer crosswalk

- [ ] Every scored criterion maps to an easy-to-find proposal location.
- [ ] Each criterion has an evidence anchor.
- [ ] Weaknesses are logged rather than hidden.
- [ ] NIH SRF applications address Importance, Rigor/Feasibility, and Expertise/Resources.
- [ ] NSF proposals explicitly address Intellectual Merit and Broader Impacts.
- [ ] Point-scored NOFOs follow the scoring order where practical.

## 9. Budget / timeline / team

- [ ] Every major work package has a budget owner.
- [ ] Every major budget line has narrative purpose.
- [ ] Personnel effort matches the work plan.
- [ ] Partner/subaward scope matches partner responsibilities.
- [ ] Timeline and milestones fit the award period.
- [ ] Budget figures match the current sponsor rules.
- [ ] Indirect-cost treatment is verified.

## 10. Citations and claims

- [ ] No fabricated or unresolved references.
- [ ] Citation claims match source scope.
- [ ] Sponsor-policy claims include current sources/review dates.
- [ ] Statistical claims resolve to data or literature.
- [ ] Regulatory claims are reviewed by appropriate institutional expertise.
- [ ] Claim language does not exceed the evidence.

## 11. Deterministic lint

- [ ] `python scripts/grant_lint.py <draft>` passes without errors.
- [ ] Warnings were reviewed individually.
- [ ] Placeholders are resolved or the proposal remains blocked.

## 12. Specialist review passes

- [ ] Eligibility/compliance review.
- [ ] Aims/objectives review.
- [ ] Significance/literature review.
- [ ] Innovation review.
- [ ] Methods/rigor/feasibility review.
- [ ] Citation audit.
- [ ] Budget/timeline/team consistency review.
- [ ] Plain-language/readability review.
- [ ] Final panel-style review against actual sponsor criteria.

## 13. Submission boundary

- [ ] Current forms are used.
- [ ] Current page limits are satisfied.
- [ ] Required attachments are present.
- [ ] Partner letters/commitments are real and current.
- [ ] Institutional sponsored-research review is complete.
- [ ] Human-subjects/clinical-trial/regulatory classifications are confirmed.
- [ ] Final human approval is recorded.
- [ ] Automated draft language has been reviewed line by line where material.

## 14. Award-to-manuscript handoff

If funded:

- [ ] Final funded aims are versioned.
- [ ] Award conditions are captured.
- [ ] Final protocol is linked to proposal claims.
- [ ] Prespecified endpoints and analyses are versioned.
- [ ] Data provenance plan is active.
- [ ] Deviations from funded protocol are logged.
- [ ] Manuscript claims remain traceable to the original proposal and subsequent evidence.
